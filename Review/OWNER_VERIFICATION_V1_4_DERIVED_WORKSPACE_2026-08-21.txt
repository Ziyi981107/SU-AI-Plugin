PURPOSE
-------
Verify the V1.4 plumbing end-to-end on a real SketchUp 2020
host. This checklist confirms:
  - the dialog's "Working Mode" section is wired correctly;
  - Prepare creates REAL plugin-owned derived groups
    (recognizable 'SU-AI-Derived-' name prefix);
  - Discard erases those groups precisely (via the
    workspace-private handle registry, NOT by dropping

    fresh ones;

  - failure paths are observed (injected host failure
    produces a `:failed` workspace + zero partial derived
    groups).

This checklist is intentionally aligned with the ACTUAL
UI capability (Prepare / Discard / Rebuild buttons in
the "Working Mode" details section; the SU-AI-Derived-*
name prefix; the source-fingerprint integrity invariant).
Items that are out of V1.4 scope are explicitly marked.

STEP V14-8: Failure injection -- abort SU operation + zero partial groups
======================================================================

This step requires you to inject a host failure during
Prepare. The V1.4 plumbing path supports this via the
Ruby console (the production adapter's `begin_operation`
is the failure surface).

The snippet below uses ABSOLUTE PATHS (paste-runnable)
and an `ensure` block to RESTORE the original method
after the test -- so V14-9 and V14-10 are NOT polluted
by the monkey-patch.

======================================================================
PASTE-RUNNABLE RUBY CONSOLE SNIPPET (V14-8)
======================================================================

  # V14-8: inject a host failure into the production
  # adapter's begin_operation. The Prepare call will fail
  # at the SU operation boundary; the workspace transitions
  # to :failed; the dialog shows it as the state.
  #
  # ABSOLUTE PATHS -- replace `D:/Projects/SU-AI-Plugin`
  # with the actual project root on your machine. The
  # rbz install root is the SketchUp Plugins/<your-rbz-folder>/
  # location; the `require_relative` here uses the project
  # source path (the V1.4 plumbing path is identical in
  # the rbz).
  require 'D:/Projects/SU-AI-Plugin/extension/su_ai_plugin/compatibility/su_derived_workspace_adapter'

  # Save the original begin_operation so the ensure block
  # can restore it.
  ADAPTER  = SUAnalysis::Compatibility::SketchupDerivedWorkspaceAdapter
  ORIGINAL = ADAPTER.instance_method(:begin_operation)

  begin
    # Monkey-patch the production adapter's begin_operation
    # to raise on the next call. The next Prepare's first
    # entity build will fail at begin_operation.
    ADAPTER.class_eval do
      define_method(:begin_operation) do |_model, label:|
        raise StandardError, 'v14-gate-2-injected-failure'
      end
    end

    # At this point, a subsequent Prepare will fail.
    # Click "Discard" first (to clear any current
    # workspace), then click "Prepare". Observe:
    #   - dialog: state = "failed", last_error visible
    #   - model: NO new SU-AI-Derived-* groups
    #   - ruby: no exception escapes

    # Wait for the Owner to do the click. There is no
    # built-in SketchUp Ruby sleep that yields to the UI;
    # leave this snippet in the console and click in the
    # dialog. When the click has run, the test is complete.
  ensure
    # RESTORE: re-define begin_operation with the original
    # implementation. After this line, V14-9 and V14-10
    # run against the original production adapter -- the
    # monkey-patch is GONE.
    ADAPTER.class_eval do
      define_method(:begin_operation, ORIGINAL)
    end
    puts 'V14-8: monkey-patch RESTORED. begin_operation is back to the production implementation.'
  end

  # If you skip the `ensure` block (e.g. close the Ruby
  # Console before it runs), the restore does NOT happen.
  # In that case you MUST restart SU + reload the
  # extension before running V14-9 / V14-10. The recovery
  # script below is the explicit restore:

  # V14-8 RECOVERY (only if the ensure block was skipped):
  #   1. Close SketchUp entirely.
  #   2. Restart SketchUp.
  #   3. Re-install the SU-AI-Plugin.rbz (or re-load the
  #      extension). The monkey-patch is gone because
  #      SketchUp reloaded the file.

STEP V14-9: Undo as an extra safety layer
======================================================================

The SU Undo stack is an extra safety layer; the V1.4
plumbing does NOT depend on Undo for correctness
(Discard is the primary discard mechanism). Per
directive: "verify Undo as an extra safety layer, not
the only discard mechanism."

  Procedure:
    1. Click Discard (clear any current workspace).
    2. Click Prepare (creates N derived groups).
    3. Press Ctrl+Z (Undo) once. Observe the SU model
       AND the Ruby console.

  Expected:
    - The most recent SU operation (one of the N build
      operations, the latest one) is undone: the last
      SU-AI-Derived-* group is removed from the Outliner.
    - The dialog state may show :discarded (the workspace
      sees an unexpected host-side change) OR may show
      :ready with N-1 entities (if the workspace is
      resilient). EITHER outcome is acceptable.
    - The source CAD is unchanged by Undo (Undo only
      touches the latest build operation; the source
      has never been touched by the workspace).

This step confirms Undo is "an extra safety layer" --
Undoing a build undoes one operation, NOT the entire
workspace. The primary discard mechanism remains the
Discard button + the workspace-private handle registry.
