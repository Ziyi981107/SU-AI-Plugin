REAL CALL CHAIN (this is what actually runs)
----------------------------------------------------------------------

Per the V1.5 directive (Guidance 031, CodeX 032 recheck):

  1. User selects N entities in SketchUp, then opens the
     SU-AI-Plugin dialog.
  2. User clicks Prepare.
     - WorkingModeRunner.prepare() captures the current
       SourceSnapshot, builds the DerivedGeometryWorkspace,
       and then AUTOMATICALLY calls
       run_duplicate_repair_batch(registry) against the
       DuplicateDetector's IssueRegistry. The Prepare
       callback auto-runs the eligible batch; there is NO
       separate "Run Duplicate Repairs" button.
  3. WorkingModeRunner.run_duplicate_repair_batch:
     a. Proposer.propose(snapshot, registry, workspace)
        -- emits 0+ :remove_duplicate_edge RepairActions
        -- full leaf identity verification (BLOCK-001)
        -- direct endpoint matcher with captured tolerance
           (BLOCK-002; proposer and validator share the
           SAME matcher semantics)
     b. Executor.apply_batch(workspace, validated_plan)
        -- preflight computes the COMPLETE post-workspace
           in pure data BEFORE opening the host operation
           (BLOCK-003)
        -- one begin, dispose all, one commit (or abort)
        -- on commit, the precomputed post-workspace is
           PUBLISHED (not constructed after commit)
     c. DerivedDuplicateValidator.validate(post_workspace)
        -- uses the captured execution_config tolerance
        -- measures duplicate_classes_after on the actual
           post-batch workspace (BLOCK-004; the validator
           no longer hard-codes 0)
     d. build_duplicate_repair_summary writes the audit
        data with REAL counts (BLOCK-004): applied/skipped/
        failed, classes before/after, pairs before/after,
        derived edge counts before/after, per-action audit
        rows. The summary is exposed via snapshot.duplicate_repair.
  4. User clicks Discard.
     - Workspace transitions to :discarded; every SU-AI-
       Derived-* group is disposed inside a single
       SketchUp operation.
  5. User clicks Rebuild.
     - Workspace is rebuilt from the captured source +
       registry; the auto-apply batch re-runs deterministically
       (same source + same registry -> same plan + same
       post-state fingerprint).

Owner verification MUST observe the real call chain above.
There is no "Run Duplicate Repairs" button; the batch is
auto-applied on Prepare (and on Rebuild).
