PURPOSE
-------
Verify the V1.5 Phase 1 vertical slice on a real SketchUp
2020 host. This checklist confirms:

  - The dialog's "Working Mode" section now shows a
    "Duplicate repairs" summary row when the
    duplicate_repair metric is recorded;
  - Prepare + Duplicate-repair auto-applies ONLY to
    exact-duplicate / reversed-exact-duplicate edge
    occurrences from the SAME source occurrence
    (same persistent_id_path);
  - Survivor selection is deterministic (lex-smaller
    derived_id wins);
  - Cross-occurrence duplicates (two distinct source
    edges that happen to share world coordinates) are
    PRESERVED (NOT removed);
  - Near-but-not-exact duplicates are PRESERVED;
  - Source CAD is NEVER mutated by the auto-repair;
  - source_fingerprint is unchanged across successful
    or failed apply;
  - Repeated apply is idempotent;
  - Discard + Rebuild work as expected;
  - Erased / invalid derived entities are skipped safely.

This checklist is intentionally aligned with the V1.5
plan §5 test matrix (SHOULD REPAIR + MUST NOT REPAIR +
APPLY SAFETY). Items out of V1.5 Phase 1 scope are
explicitly marked.

PREREQUISITES
-------------
1. dist/SU-AI-Plugin.rbz has been BUILT from the
   v1.5-high-confidence-auto-repair HEAD. The Agent
   rebuilt the rbz before dispatch; you do NOT need
   to rebuild yourself.
2. The rbz is INSTALLED on a real SketchUp 2020 (NOT
   SketchUp 2017; SU2017 is a separate release gate).
4. A test model is ready that has BOTH:
   - (a) the SAME source edge recorded twice in the
     source data (creates 2 derived records with the
     SAME source_occurrence_id -- SHOULD REPAIR case);
   - (b) two DISTINCT source edges from DIFFERENT
     component instances that happen to share world
     coordinates (creates 2 derived records with
     DIFFERENT source_occurrence_ids -- MUST NOT REPAIR
     case).
5. The V1.5 menu item "Analyze selection" is reachable
   from the Plugins menu (same as V1.0-V1.4).

The "V15-N" steps below mirror the V1.5 plan §5 test
matrix (1..14). Each step has a single expected
outcome. Mark PASS or FAIL per step on real SU2020.

If the production-side `duplicate_repair` flow is not
yet wired into the dialog's Prepare / Discard buttons
(V1.5 Phase 1 keeps the executor as a pure-Ruby
helper -- the dialog does NOT auto-trigger the apply),
the Owner can verify the auto-repair via the V15-N

Proposer + DuplicateRepairExecutor are all pure-Ruby
helpers and the test suite has already proven the
end-to-end behavior (21 tests in
tests/test_v15_duplicate_repair.rb; 677/677 total).

STEP V15-1: SHOULD REPAIR — Forward exact duplicate
======================================================================

PREPARE:
  - Select a source edge entity that is recorded TWICE
    in the source data (same persistent_id_path; the
    DuplicateDetector emits a `duplicate_edge_candidate`
    issue).
  - Verify the dialog summary text shows "Duplicate
    Candidates: 1" (or more if there are additional
    pairs).
  - Click Prepare. Verify the workspace has 2 derived
    records (one per source edge record) for the same
    source occurrence.

AUTO-REPAIR:
  - Trigger the duplicate repair (via the dialog's
    "Duplicate repairs" affordance if available, or via
    a Ruby console call to
    `SUAnalysis::Core::DuplicateRepairExecutor.apply(...)`).
  - Verify: the workspace now has 1 derived record
    (the survivor).
  - Verify: the survivor's derived_id is the
    LEX-SMALLER of the two pre-existing derived_ids
    (deterministic rule).
  - Verify: source CAD is unchanged (source_fingerprint
    digest matches the pre-apply value).

  Expected: workspace entity_count drops from 2 to 1;
            survivor = lex-smaller derived_id;
            source unchanged.
  Capture: pre/post source_fingerprint digest + entity
           count + survivor derived_id.

======================================================================
STEP V15-2: SHOULD REPAIR — Reversed exact duplicate
======================================================================

PREPARE:
  - Select two source edge records with the SAME
    persistent_id_path but REVERSED endpoints (A->B
    and B->A).
  - Verify the DuplicateDetector emits a
    `duplicate_edge_candidate` issue.

AUTO-REPAIR:
  - Apply the repair. Verify: workspace has 1 derived
    record (the survivor).
  - Verify the action's `confidence_basis` is
    `reversed_endpoint_match_within_tolerance.duplicate`
    (NOT `exact_endpoint_match_within_tolerance.duplicate`).

  Expected: workspace has 1 survivor; basis names the
            reversed match.
  Capture: pre/post entity count + action confidence_basis.

======================================================================
STEP V15-3: SHOULD REPAIR — Three identical edges
======================================================================

PREPARE:
  - Select THREE source edge records with the SAME
    persistent_id_path and the same endpoints.
  - Verify the DuplicateDetector emits C(3,2)=3 pairwise
    issues (one per pair).

AUTO-REPAIR:
  - Apply the repair. Verify: workspace has 1 derived
    record (the lex-smallest survivor).
  - Verify the action emits ONE :remove_duplicate_edge
    action (not 3) -- the proposer collapses same-
    occurrence pairs into one action per occurrence.

  Expected: workspace entity_count drops from 3 to 1;
            ONE action emitted, removing 2 derived
            records.
  Capture: pre/post entity count + action count.

======================================================================
STEP V15-4: MUST NOT REPAIR — Shared-definition two instances
======================================================================

PREPARE:
  - Create two ComponentInstances of the same
    ComponentDefinition (4-edge definition).
  - Select both instances (or all the edges they
    contain).

AUTO-REPAIR:
  - Apply the repair. Verify: workspace entity_count
    is UNCHANGED. The two component instances have
    DIFFERENT source_occurrence_ids (different
    persistent_id_path) -- V1.5 Phase 1 MUST NOT
    merge distinct shared-component occurrences.

  Expected: workspace entity_count unchanged; action
            is :skipped with reason
            `source_occurrence_ids_differ`.
  Capture: pre/post entity count + skipped action count.

======================================================================
STEP V15-5: MUST NOT REPAIR — Short edge preserved
======================================================================

PREPARE:
  - Create a short edge (length below
    `tolerance.short_edge`, default 0.5 inches).
  - No duplicate evidence.

AUTO-REPAIR:
  - Apply. Verify: workspace entity_count unchanged.
    V1.5 Phase 1 does NOT auto-delete a short edge
    merely because its length is below the threshold.

  Expected: no removal; workspace unchanged.
  Capture: pre/post entity count.

======================================================================
STEP V15-6: MUST NOT REPAIR — Near-but-not-exact duplicate
======================================================================

PREPARE:
  - Create two source edges with endpoints just
    outside the duplicate tolerance (e.g., 0.001
    inches apart when tolerance.duplicate = 0.0001).

AUTO-REPAIR:
  - Apply. Verify: workspace entity_count unchanged.
    V1.5 Phase 1 does NOT handle approximate /
    fuzzy duplicates.

  Expected: no removal; workspace unchanged.
  Capture: pre/post entity count.

======================================================================
STEP V15-7: MUST NOT REPAIR — Same world coords, different
             source_occurrence_ids preserved (provenance gate)
======================================================================

PREPARE:
  - Create two source edges with EXACT same world
    coordinates but DIFFERENT persistent_id_path
    (e.g., one in a nested group, one at the root,
    OR two component instances of the same definition).

AUTO-REPAIR:
  - Apply. Verify: workspace entity_count unchanged.
    The provenance gate (same source_occurrence_id
    required) prevents removal.

  Expected: no removal; action :skipped with reason
            `source_occurrence_ids_differ`.
  Capture: pre/post entity count.

======================================================================
STEP V15-8: MUST NOT REPAIR — Self-match
======================================================================

PREPARE:
  - Force the analyzer to emit a duplicate_pair for
    the same edge twice (edge_ids = [N, N]).

AUTO-REPAIR:
  - Apply. Verify: workspace entity_count unchanged.
    The proposer emits :skipped with reason
    `duplicate_evidence_self_match`.

  Expected: no removal; action :skipped with
            duplicate_evidence_self_match basis.
  Capture: pre/post entity count + skipped action count.

======================================================================
STEP V15-9: MUST NOT REPAIR — Nested transform
======================================================================

PREPARE:
  - Create two source edges with the same world
    coordinates but DIFFERENT persistent_id_path
    (one nested inside a group, one at the root).

AUTO-REPAIR:
  - Apply. Verify: workspace entity_count unchanged.
    The nested transform case is preserved.

  Expected: no removal; workspace unchanged.
  Capture: pre/post entity count.

======================================================================
STEP V15-10: APPLY SAFETY — Repeated apply idempotent
======================================================================

PREPARE + AUTO-REPAIR:
  - Apply the repair from V15-1 once (workspace -> 1
    entity).
  - Apply again with the same plan. Verify: second
    apply is a no-op (action transitions to :skipped
    with `already_applied` reason). workspace entity
    count unchanged.

  Expected: workspace has 1 entity after both applies;
            second action :skipped.
  Capture: applied[1].status.

======================================================================
STEP V15-11: APPLY SAFETY — Mid-action failure rollback
======================================================================

PREPARE:
  - Build the V1.5 workspace. Inject a host failure on
    dispose() (per the V14-8 label-targeted one-shot
    patch pattern; this is testable via the dialog's
    failure-injection hook or a Ruby console call).

AUTO-REPAIR:
  - Apply the repair. Verify: workspace transitions to
    `:failed` with `last_error` referencing the dispose
    failure.
  - Verify: ALL handles are preserved (no partial
    removal).
  - Verify: source CAD unchanged.

  Expected: workspace state = :failed; entity count
            unchanged; source_fingerprint unchanged.
  Capture: new_ws.state, new_ws.last_error,
           pre/post source_fingerprint.

======================================================================
STEP V15-12: APPLY SAFETY — Discard + rebuild after apply
======================================================================

PREPARE + AUTO-REPAIR:
  - Apply the repair from V15-1.
  - Discard. Verify: workspace :discarded, 0 entities.
  - Rebuild. Verify: rebuilt workspace is :ready with
    the same survivor derived_id (1 entity).
  - Verify: source_fingerprint unchanged across the
    discard + rebuild cycle.

  Expected: rebuilt workspace matches pre-discard
            post-apply state; source unchanged.
  Capture: rebuilt_ws.entities.first.derived_id;
           pre/post source_fingerprint.

======================================================================
STEP V15-13: APPLY SAFETY — Erased / invalid derived entity
======================================================================

PREPARE:
  - Build the V1.5 workspace with 2 derived records.
  - Manually erase one of the host handles (e.g., via
    a Ruby console call to `g.erase!` on the underlying
    FakeGroup / SketchUp::Group).

AUTO-REPAIR:
  - Apply. Verify: the erased handle is silently
    filtered out (no raise); the remaining valid
    derived record(s) are processed normally.

  Expected: no raise; erased entity skipped silently;
            workspace still has 1 entity (survivor).
  Capture: applied status, final entity count.

======================================================================
STEP V15-14: APPLY SAFETY — source_fingerprint unchanged
======================================================================

PREPARE + AUTO-REPAIR:
  - Capture source_fingerprint BEFORE apply.
  - Apply the V15-1 repair.
  - Capture source_fingerprint AFTER apply.
  - Verify: digests are identical.

  Expected: source_fingerprint.digest unchanged.
  Capture: pre/post source_fingerprint.digest.
