(The first line is a no-op for the real SketchUp install; it

"V15-0 FAIL: <module-name> not defined".

STEP V15-1: SHOULD REPAIR — Duplicate edge inside one ComponentInstance
======================================================================

PREPARE A REAL TEST FIXTURE:

  1. Open your test model.
  2. Select the entire model (Ctrl+A or Edit > Select All).
  3. Plugins > SU-AI-Plugin > Analyze selection.
  4. Wait for the dialog to render.

Inside the dialog, scroll DOWN to "Working Mode (V1.4)" (the
last details block).

EXPECTED in the Working Mode list before any click:
  state:        none
  entities:     0
  rows:         1 idle row "No working copy yet..."
  Duplicate repairs row: NOT present

CLICK "Prepare".

EXPECTED in the Working Mode list AFTER Prepare:
  state:                  ready
  entities:               (depends on your model)
  Duplicate repairs row:  present with the text
                         "Duplicate repairs: applied N, skipped M"
                         where N >= 1 (the duplicate from your
                         ComponentDefinition) and M >= 0.

The dialog's "Entities ready" number will be ONE LESS than the
number of distinct world-coordinate edge occurrences in your
selection, because Phase 1 removed the duplicate(s).

VERIFY in the model OUTSIDE the dialog:
  - Select the ComponentInstance you prepared.
  - Look at Outliner: the ComponentInstance's definition
    still contains 2 (or more) SU Edges with the duplicate
    world coords (NOT removed). The plugin REMOVES derived
    copies, NOT the source edges.
  - Ctrl+Z (Undo) once: the derived groups disappear; the
    ComponentInstance's edges are untouched.

  Expected: derived groups + source edges unchanged.

STEP V15-2: SHOULD NOT REPAIR — Shared definition, two instances
======================================================================

PREPARE A REAL TEST FIXTURE:

  1. In your model, place a SECOND ComponentInstance of the
     same ComponentDefinition. The model now has two instances
     sharing the same world-coordinate edges.
  2. Select both instances (or select all and Analyze).
  3. Plugins > SU-AI-Plugin > Analyze selection.
  4. CLICK Prepare.

EXPECTED: The "Duplicate repairs" row in Working Mode reports
"applied 0, skipped >= 2" (each shared-definition duplicate
pair is preserved because the two instances have different
container paths in the SU hierarchy).

  Expected: NO derived groups removed. The "applied" count is
            ZERO.

This proves the shared-component isolation rule (master plan §17.2).

    pre-apply and post-rebuild.
  - The "Duplicate repairs" row appears with the same applied
    / skipped counts as the original (deterministic rebuild).

  Capture the digest BEFORE Discard and AFTER Rebuild; they
    MUST match.

STEP V15-4: Mid-action failure rolls back the whole batch
======================================================================

This step requires Ruby Console access (no GUI operation can
inject a host failure during the production chain). The
Owner uses the Console to invoke the exact production chain
with an injected adapter failure.

PASTE in the Ruby Console (with the dialog open from V15-1):

    # Capture the controller's current AnalysisResult.
    ar = $su_ai_plugin_dialog_controller.result
    # Inject a one-shot host failure into the workspace's
    # adapter's dispose path.
    ws = SUAnalysis::Core::WorkingModeRunner.current_workspace_for_test
    ws.instance_variable_get(:@adapter).instance_variable_set(
      :@next_dispose_should_raise,
      StandardError.new('v15-gate-injected-failure')
    )
    # Re-run the production chain.
    SUAnalysis::Core::WorkingModeRunner.run_duplicate_repair_batch(
      registry: ar.registry
    )

(If `$next_dispose_should_raise` is not a hook in your installed
adapter, the Agent has wired a generic one-shot adapter failure
in `extension/su_ai_plugin/compatibility/su_derived_workspace_adapter.rb`.
If the hook name is different, look at the adapter file for the
current hook name.)

EXPECTED:
  - The Workspace state becomes "failed" with last_error mentioning
    "v15-gate-injected-failure".
  - The "Duplicate repairs" row shows "applied 0, failed 1".
  - The model's derived groups are UNCHANGED (no partial removal).
