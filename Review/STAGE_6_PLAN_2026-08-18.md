## 2. What V1.0 UI does and does NOT do

### Does
- Display CAD Analyzer Result header (summary metrics).
- Display issue list grouped by `issue_type`, each section collapsible,
  with `(NN)` count in the heading.
- Render severity badge per issue (`:low` neutral / `:medium` orange /
  `:high` red).
- On Issue row click: call `selection.add(issue.source_entity)` + a
  camera zoom-to-bbox of the source entity geometry, then nothing.
- Close button + Esc.

### Does NOT (V1.0 — per PI_TASK_001 §17 / §91 / R003 hard prohibition)
- Add any entity / material / layer / tag / face / edge / group /
  component / construction line / construction point / construction
  geometry to the model — even create-and-erase.
- Auto-fix anything.
- Mutate any source entity property (material, layer, visibility,
  soft/hidden, color, dictionary entries, attributes).
- Provide filter / sort / search controls.
- Provide entity info / attribute viewer / persistent-id browser.
- Provide settings UI.
- Provide per-Issue highlight overlay (R003 Q3.1=B).
- Provide multi-Issue multi-select ("frame all").
- Provide any "Re-run" / "Refresh" button (UI is opened once per
  analysis run; analysis is triggered by the existing menu item that
  exists in Stage 2 / pre-Stage-6 scripts).
- Persist any state across sessions (no write to file / registry).


## 3. Hard-line module boundary (per R003 + R005 + PI_TASK_001 §14)

```
                    ┌──────────────────────────────────────────────┐
                    │   extension/  (the only place Sketchup::*    │
                    │                is allowed)                   │
                    │                                              │
                    │   preflight_runner.rb   (Stage 2; COMPLETE)   │
                    │   analyzers_runner.rb   (NEW Stage 6)        │
                    │   dialog_runner.rb      (NEW Stage 6)        │
                    │   ui_bridge.rb          (NEW Stage 6)        │
                    │                                              │
                    │   html/                                       │
                    │     index.html        (NEW Stage 6)          │
                    │     style.css         (NEW Stage 6)          │
                    │     app.js            (NEW Stage 6)          │
                    │                                              │
                    ├──────────────────────────────────────────────┤
                    │   compatibility/su_capability.rb             │
                    │   (existing; only `html_dialog?` is new)     │
                    ├──────────────────────────────────────────────┤
                    │   core/  (pure Ruby; NO `Sketchup::`)        │
                    │     - PreflightReport, EdgeRecord, …         │
                    │     - IssueRegistry      (NEW Stage 6)       │
                    │     - IssueGrouper      (NEW Stage 6)       │
                    │     - IssueIdAssigner   (NEW Stage 6)       │
                    └──────────────────────────────────────────────┘
```

**Rules**:

1. `core/` must NOT `require` `Sketchup::*` or anything in `extension/`.
2. `compatibility/` only does `respond_to?` / `defined?` probes; it
   does NOT call mutators.
3. `extension/` is the only place that constructs a `UI::HtmlDialog`,
   and the only place that calls `model.selection.add` / `view.zoom`.
4. The HTML / CSS / JS files in `extension/html/` are static assets
   referenced by relative path; they are NOT loaded as Ruby code.
5. UI never directly reads `model` / `selection` — it only receives a
   serialized snapshot via `ui_bridge.rb` (JSON-ish Array of Hashes).
   This makes the HTML renderable in a unit test (no SU required).
6. UI never receives a callable that could mutate the model. The
   only Ruby callback exposed to JS is `locate_issue(issue_id)`,
   which is a read-only lookup + non-mutating `selection.add` + a
   non-mutating camera `zoom`.

## 6. Critical implementation rules

### 6.1 NO overlay / NO mutation enforcement (R003 hard prohibition)

**Strategy**:

1. **Code-level prohibition**: scan `extension/ui_bridge.rb` and
   `extension/dialog_runner.rb` for any of the following forbidden
   method calls; the test suite must include a static lint that
   raises if any of them appear in `extension/` (except in
   `tests/_fake_su.rb`):

   ```
   Forbidden (case-sensitive, whole-token) in extension/:
     .add_cpoint, .add_cline, .add_face, .add_group,
     .add_component_instance, .add_image, .add_text,
     .add_3d_text, .add_section_cut, .entities.add_*,
     .materials.add, .layers.add, .tags.add,
     .attribute_dictionary, .set_attribute, .material =,
     .layer =, .back_material =, .soft=, .hidden=,
     .erase_entities, .start_operation, .commit_operation
   ```

   The static lint lives in `tests/test_no_overlay_lint.rb` and runs
   as part of `tests/run_all.rb`. A single hit → `FAIL`.

2. **Comment marker**: an `extension/dialog_runner.rb` block comment
   at the top reproduces the R003 hard prohibition verbatim, so
   future Agents cannot miss it.

3. **Manual verification gate**: `Review/OWNER_VERIFICATION_STAGE_2.txt`
   gets a Stage 6 addendum requiring Owner to:
   - Open dialog on a known disposable Group.
   - Run their CAD through Analyze.
   - Click every issue type.
   - Confirm via Entity Info that the source entity properties
     (material, layer, hidden, soft, dictionary entries) are
     IDENTICAL pre- and post-click.
   - Confirm there are no new entities / materials / layers in the
     `.skp` file (use `Window → Model Info → Statistics` delta).

### 6.2 Capability fallback (R002 / R003 Q3.2)

`SUCapability.html_dialog?` returns `true` on SU2017+ real SU. It
must return `false` on host lacking `UI::HtmlDialog`. Stage 6
fallback path:

- If `false`, write a single-line message to `STDOUT` (Ruby
  `puts`) with severity banner + a `UI.messagebox(...)` summary,
  listing the missing UI capability and the SU version detected.
  The Owner Report marker "NOT VERIFIED IN REAL SKETCHUP" is
  still safe to write; the fallback is testable in unit tests via
  the `FakeUI::*` stub.

The fallback MUST NOT silently open a WebDialog (legacy) or
attempt to use `Sketchup::HtmlDialog` (wrong namespace; broken per
S2-BLOCK-006).

### 6.3 Locate action — non-mutating breakdown

Per PI_TASK_001 §13 + R003 Q3.5: click = Locate only.

Non-mutating means:
- `model.selection.add(entity)` does NOT mutate the source entity.
  It only mutates `Selection`, which is view-state, not model
  state. This is allowed per Codex Review 005 §R003 ("Selection /
  camera state are OK because they don't change source entity
  geometry or properties").
- `view.zoom(entities)` mutates the camera, not the model. Allowed.
- A redrawing CSS class on the clicked row is DOM-only, not
  SketchUp state. Allowed.

The test `tests/test_dialog_runner.rb` will assert that
`locate_issue` calls ONLY `selection.add` and `view.zoom` on the
FakeView — any other method call is a test failure.

### 6.4 Issue ID determinism (R005)

`issue_id` is a String of the form
`{issue_type}:{persistent_id_path_or_signature}:{counter_within_type}`.

- `persistent_id_path` joins the entity's container + entity PIDs
  with `.` (matches `SUCapability.serialize_pid_path`).
- When `persistent_id_path` is unavailable (e.g. test env without
  `_fake_su.rb` PIDs), fall back to a deterministic geometry
  signature: `"{start_x}|{start_y}|{start_z} -> {end_x}|{end_y}|{end_z}"`
  quantized at coord epsilon.
- Counter is per-registry, per-type — ensures constant order
  even when sources are identical (e.g. duplicate edges).
- `issue_id` MUST be a String (no Symbol, no Integer) to avoid
  freeze-from-respond_to? traps and to make it JSON-friendly.

### 6.5 Severity canonicalization (R005)

- All issues that reach the UI have severity `:low / :medium / :high`.
- `IssueRegistry` raises at construction time if any issue has
  a non-canonical severity. This is a hard test in
  `test_issue_registry.rb`.
- Stage 2 PreflightAnalyzer already emits `:low / :medium / :high`
  per Codex Review 004 / 005 / 008 passes (S2-BLOCK-004 closed).
- The 4 analyzers in `core/analyzers/` already use canonical
  severities.
- Stage 6 just freezes the contract; no new mapping needed.

### 6.6 Group ordering (R005)

Top-to-bottom order on the page:
1. Group by `issue_type` in this order: `duplicate_edge_candidate`,
   `short_edge`, `open_endpoint`, `gap_candidate`,
   `non_zero_z_geometry`, `large_coordinate`, `deep_nesting`.
   (Defines the "all visible groups" walk for the Owner.)
2. Within each group, sort by `issue_id` ASC (lexicographic).
3. Each group is a `<details>` element; default `open` iff the
   `:high` count in the group > 0; else `closed`. Visually
   consistent and reduces scrolling.

### 6.7 Summary header

A two-line header at the top of the page:

```
CAD Analyzer Result
Selection: Group "X"   Edges: 1234   Vertices: 678
```

Lines:
- Title: "CAD Analyzer Result".
- Selection type + name (from `PreflightReport.selection_type` +
  root container `.name`).
- Counts: `Edges: NN`, `Vertices: NN`, `Duplicate candidates: NN`,
  `Short edges: NN`, `Open endpoints: NN`, `Gap candidates: NN`,
  `Non-zero-Z vertices: NN`, `Warnings: NN` (warnings = sum of
  `:medium` + `:high` issues).

### 6.8 Ruby 2.2.4 syntax discipline

Every new file follows the same rules as Stage 2:
- No `&.` safe-navigation.
- No `case/in` pattern matching.
- No `(param =)` shorthand.
- No `def foo() = expr` endless defs.
- No `frozen_string_literal: true` magic comment.
- No `_1`, `_2` numbered params.
- No `$ERROR_INFO` (use `$ERROR_MESSAGE`).
- Strings use `to_s` explicitly on any object that could be a
  `Float` / `Integer` / `nil`.
- All `require` are `require_relative` (no gem deps).

A new file-level check `tests/test_ruby_22_syntax_sweep.rb`
extends the existing sweep to include `core/issue_*`,
`extension/analyzers_runner.rb`, `extension/dialog_runner.rb`,
`extension/ui_bridge.rb`. Existing sweep covers 17/17 files; the
new target is ~22/22.

### 6.9 JS contract discipline

- No `eval`, no `new Function`, no `document.write`, no `innerHTML`
  for user-supplied strings.
- All interop data is JSON-shaped (String, Number, Boolean, Array,
  Object). No functions, no Symbols, no Dates.
- Click handler is the only outbound call. No push to SU.
- The `locate_issue` callback receives ONLY a `issue_id` String.
- The "close" callback is for UI shutdown only — no model access.
- All issue data (label, message, severity) is rendered through
  `textContent` / `setAttribute('data-…')`, never `innerHTML`.

### 6.10 Error handling (PI_TASK_001 §18)

Every external boundary call has a `rescue StandardError`:
- `extension/analyzers_runner.rb`: per-analyzer rescue; one bad
  analyzer MUST NOT stop the others.
- `extension/dialog_runner.rb#locate_issue`: if the source entity
  is no longer resolvable (erased, etc.), write to SU console and
  no-op. NEVER raise to the JS layer.
- `core/issue_id_assigner.rb`: if PIDs are missing, fall back to
  geometry signature; never raise.
- `extension/ui_bridge.rb`: serialization MUST be lossy-tolerant
  (missing fields render as "—" not throw).
