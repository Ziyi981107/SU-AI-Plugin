ROOT CAUSE OF BLOCK-002-R2
=========================

Counter assignment in `enrich_all` sorted only by canonical_source_keys.
When two logical Issues of the same type shared the same source keys
(e.g., two open endpoints of one Edge with the same PID path) but
differed in location, the counter was assigned in input order and
was therefore unstable.

CodeX reproduction (verbatim):
  input [location 0, location 10]  -> location 10 gets |1; location 0 gets |2
  input [location 10, location 0]  -> location 0 gets |1; location 10 gets |2

FIX
===

core/issue_enricher.rb: enrich_all now sorts each type bucket by a
COMPLETE deterministic issue key composed of:

  1. canonical source keys (PID paths or geometry fallback)
  2. quantized location (or "loc:none" when absent)
  3. sorted edge_ids (or "edges:" empty when absent)

Counter remains the FINAL tie-breaker only after the complete stable
key. entity_id, object_id, traversal order, and input position are
NOT used in the sort key.

New private method:
  stable_sort_key(issue, coord_epsilon: 1.0e-6) -> String

The issue_id format itself is unchanged: "{type}|{source_keys}|{counter}".
What changed is the COUNTER ASSIGNMENT; once the sort is stable, the
counter is stable, and therefore the issue_id is stable.

Files in this fix:
  core/issue_enricher.rb          (M, +stable_sort_key)
  tests/test_issue_enricher.rb    (M, +2 adversarial tests)
