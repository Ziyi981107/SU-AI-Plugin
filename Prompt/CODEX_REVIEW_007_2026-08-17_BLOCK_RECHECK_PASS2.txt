1. S2-BLOCK-002 — REMAINS OPEN
   Location:
   - compatibility/su_capability.rb:198-213, 231-273
   - extension/preflight_runner.rb:64-92
   - tests/fake model and round-2 PID/edit-context tests

   Problem:
   The implementation and fakes use a non-real active-path/PID contract.
   Real Model#active_path is an Array of drawing elements, not an
   InstancePath-like object. Therefore it does not provide
   persistent_id_path or transformation. The current code consequently
   returns an identity/nil transform and an empty PID prefix during a real
   nested edit session.

   Model#instance_path_from_pid_path expects a dot-delimited persistent-ID
   path String. Current resolve_pid_path passes Array<Integer> directly.
   The fake model accepts that array and therefore masks the production
   failure.

   build_source_reference also still writes entity.object_id as entity_id
   unconditionally. Use entity.entityID when available; object_id may only
   be the final outside-SU/test fallback.

   Why it matters:
   Nested edit-context world coordinates and machine-resolvable source
   references are core Stage-2 requirements. The current implementation can
   pass unit tests while producing incorrect coordinates and unresolvable
   references in SketchUp.

   Minimum acceptable fix:
   - Get the edit transform from model.edit_transform.
   - Treat model.active_path as Array; obtain each element's safe persistent
     ID to seed the container path.
   - Define one canonical PID-path representation. For the SketchUp resolver,
     pass a dot-delimited String such as "10.20".
   - If an InstancePath is constructed, validate it with the real documented
     shape and serialize InstancePath#persistent_id_path as String.
   - Use entity.entityID when supported; object_id only as fallback.
   - Correct the fakes so active_path is Array, edit_transform belongs to
     Model, persistent_id_path is String, and resolver rejects arrays.

   Recheck evidence needed:
   - Tests using the corrected real API-shaped fakes.
   - Active nested edit-context test proving exact world coordinates.
   - PID path emitted by a snapshot resolves through a String-only resolver.
   - Shared-definition multi-occurrence tests remain passing.

2. S2-BLOCK-004 — REMAINS OPEN
   Location:
   - core/preflight.rb:226-251
   - tests/test_preflight.rb:311-324

   Problem:
   OR semantics, configured coordinate_epsilon propagation, and nominal
   performance are fixed. However, distinct-vertex collection searches only
   the point's exact quantized bucket. Two points within epsilon but on
   opposite sides of a bucket boundary are not compared.

   Reproduction:
   With coordinate_epsilon=1.0, points [0.99,0,0] and [1.01,0,0] are only
   0.02 apart but the current result contains two distinct vertices.

   Why it matters:
   Preflight counts depend on coordinate_epsilon. Boundary-dependent counts
   violate the configured tolerance contract and can change warnings for
   geometrically equivalent data.

   Minimum acceptable fix:
   - Prefer reusing the already-built snapshot VertexIndex/source of truth; or
   - search the current bucket plus all adjacent buckets and retain the
     explicit epsilon comparison before accepting a new point.
   - Preserve near-linear behavior for the 5,000-edge case.

   Recheck evidence needed:
   - Regression with points straddling a bucket boundary.
   - Existing custom-epsilon, correctness, and performance tests pass.

3. S2-BLOCK-005 — REMAINS OPEN
   Location:
   - Review/OWNER_VERIFICATION_STAGE_2.txt:149-205
   - extension/preflight_runner.rb invalid-entity handling

   Problem:
   Production invalid-entity handling is materially improved, and unit tests
   now prove invalid geometry is skipped rather than synthesized at origin.
   The required real-SketchUp verification checklist is still not executable
   and complete:

   - Entities#add_line returns one Sketchup::Edge, not an array. The checklist
     uses add_line(...)[0], so e1 is not the intended Edge.
   - Erasing an edge and then analyzing only its parent entities collection
     does not retain that erased reference; it weakly tests a different path.
   - The fingerprint directly calls definition.persistent_id, which is not a
     safe SU2017-baseline assumption for ComponentDefinition.
   - The fingerprint does not fully recurse component-definition contents and
     occurrence transforms, so it can miss source changes inside components.

   Why it matters:
   S2-BLOCK-005 explicitly requires credible real-host evidence that analysis
   survives invalid references and does not mutate source geometry. The
   current checklist can fail for the wrong reason or report a false pass.

   Minimum acceptable fix:
   - Assign e1 = entities.add_line(...) directly.
   - Exercise a retained erased/invalid reference together with a valid edge,
     then prove the valid edge is analyzed and the invalid one contributes
     zero records. If SketchUp prevents this exact selection shape, record the
     actual host behavior and use the closest reproducible invalidation path.
   - Make fingerprint PID access capability-safe for SU2017.
   - Recursively fingerprint group and component contents plus occurrence
     transforms/counts required to detect source mutation.
   - Keep before/after fingerprinting around analysis only.

   Recheck evidence needed:
   - Corrected, paste-runnable SU2017+ checklist.
   - Recorded real SketchUp results for source fingerprint and invalid entity
     behavior.
