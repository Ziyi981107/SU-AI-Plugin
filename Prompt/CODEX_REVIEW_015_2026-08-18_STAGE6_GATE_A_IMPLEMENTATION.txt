1. [S6-GATE-A-BLOCK-001] Leaf is incorrectly counted as structural nesting

   Location:
   - core/structural_facts.rb:47-55 and 73
   - core/issue_enricher.rb:119
   - tests/test_structural_facts.rb root cases

   Problem:
   `StructuralFacts.compute` and `from_canonical_path` calculate:
       structural_depth = active_path_count + ancestry_count + 1
   The `+1` counts the leaf Entity itself. `IssueEnricher` then defines:
       nested = src.structural_depth > 0
   Therefore a root-level Edge has structural_depth=1 and is classified as nested.

   This contradicts the locked locator contract used throughout the plan and previous
   reviews:
       root-level leaf -> structural_depth 0 / nested false
       one enclosing Group/Component -> structural_depth 1 / nested true
       expected_pid_count = structural_depth + 1 (the +1 is the leaf PID)

   Consequences:
   - a root Edge with missing PID cannot use the allowed root entityID fallback;
   - a complete root Edge can be routed to InstPath#root instead of InstPath#leaf;
   - Gate B will receive incorrect SourceToken profiles even if its adapter is correct.

   Minimum acceptable fix:
   - Define structural_depth as the count of structural ancestor containers/edit-path
     entities, excluding the leaf.
   - Root leaf: depth 0; two ancestors: depth 2.
   - Keep full-path completeness invariant:
       expected_pid_count = structural_depth + 1
   - Ensure active edit-path entities and walked container ancestry are not double-counted.
   - Update StructuralFacts tests and add an integration test that pipes its root result
     through SourceReference -> IssueEnricher -> IssueLocatorPolicy:
       complete root -> :inst_path_leaf
       incomplete root + entityID -> :entity_id
   - Retain nested complete/incomplete controls.

   Recheck evidence needed:
   - focused diff + corrected structural tests + full suite

2. [S6-GATE-A-BLOCK-002] Issue IDs still use transient identity and input-order counters

   Location:
   - core/issue_id_assigner.rb:57-68
   - core/issue_enricher.rb:70-89
   - tests/test_issue_id_assigner.rb and test_issue_enricher.rb

   Problem A — forbidden fallback:
   `geometry_signature` falls back to:
       "entity_id:#{token[:entity_id]}"
       "anon:#{token.object_id}"
   Both directly violate the locked requirement that issue_id NEVER use entity_id or
   object_id. The existing test passes only because it supplies a PID or location and
   never exercises these branches.

   Problem B — unstable counter assignment:
   `IssueEnricher.enrich_all` groups in input order and calls `list.each_with_index`
   without sorting by canonical source/semantic keys first. Reversing analyzer output can
   change the counter suffix assigned to the same logical Issue, so its issue_id changes
   across equivalent runs.

   Why it matters:
   HtmlDialog callbacks address Issues by issue_id. IDs must be deterministic for stable
   ordering, rendering and lookup. Runtime Ruby object identity is explicitly unsuitable.

   Minimum acceptable fix:
   - Delete every entity_id/object_id issue-id fallback.
   - For missing PID and missing location, use only deterministic analysis data, such as
     a canonical issue-level signature from issue_type + sorted edge_ids + sanitized
     semantic metadata/message; a constant no-source key plus deterministic semantic
     tie-breaker is also acceptable for preflight warnings.
   - Before assigning counter_within_type, sort each type bucket by a complete canonical
     stable key. Counter remains the final tie-breaker.
   - Add tests that force the no-PID/no-location branches and assert the ID contains
     neither entity_id nor object_id-derived data.
   - Add a permutation test: enrich the same logical Issues in reversed/shuffled input
     order and assert each logical Issue receives the same issue_id.

   Recheck evidence needed:
   - focused diff + adversarial ID tests + full suite
