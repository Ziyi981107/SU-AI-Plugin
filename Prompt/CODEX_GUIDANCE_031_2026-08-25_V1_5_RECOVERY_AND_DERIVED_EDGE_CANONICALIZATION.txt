5. LOCKED AUTO-APPLY ELIGIBILITY
======================================================================

A duplicate-edge equivalence class is auto-applicable only when ALL are true:

  1. Evidence originates from existing duplicate_edge_candidate issues in the
     captured IssueRegistry. Do not add a competing analyzer.
  2. Every member resolves to a distinct source EdgeRecord and a distinct live
     derived Edge record/handle in the current workspace.
  3. World-coordinate endpoints match forward or reversed within the CAPTURED
     execution_config tolerance.duplicate. Re-verify directly; bucket membership
     alone is never sufficient.
  4. Coordinates are finite and transform resolution was valid.
  5. Every member belongs to the same current SourceSnapshot/selection scope.
  6. Provenance is usable. Incomplete nested identity fails closed.
  7. Layer names are byte-identical after the existing Layer0 normalization.
     Different layer names/semantic sources are ambiguous and MUST be skipped.
  8. No member is a self-match or a repeated reference to the same source edge.
  9. No member depends on short-edge status as deletion evidence.
 10. No source entity is written, erased, moved, relayered, transformed, or
     reparented.

Any failed guard produces an auditable skipped action/reason. It must not silently
drop the issue or guess user intent.

Explicit non-eligible cases:
  - near/approximate duplicates outside tolerance;
  - layer mismatch;
  - incomplete nested provenance;
  - invalid/erased source or derived handle;
  - self-match;
  - different world coordinates, including normal shared-definition instances
    at different transforms;
  - short edge solely because it is short;
  - face/gap/weld/flatten/loop/site/AI/MCP/V2 work.

6. PROPOSER CONTRACT
======================================================================

Refactor DuplicateRepairProposer around derived world-geometry equivalence, not
same-container identity.

Requirements:

  - Consume only duplicate_edge_candidate registry evidence.
  - Build deterministic equivalence classes, not one action per pair. N exact
    coincident edges produce ONE action removing N-1 derived records.
  - Prevent overlapping actions: one derived_id may belong to only one action.
  - Canonical geometry key is orientation-independent and based on the captured
    world endpoints plus the required direct tolerance verification.
  - Deterministic survivor: lexicographically smallest derived_id.
  - Deterministic source provenance union: sorted unique source_occurrence_ids
    from every contributing derived record.
  - Deterministic action_id derived from rule id + snapshot identity + canonical
    geometry key + sorted member derived_ids. Do not use SecureRandom for actions
    that must be reproducible/auditable.
  - The action records:
      survivor_derived_id;
      removed derived IDs;
      complete source_occurrence_ids union;
      canonical endpoint summary;
      layer;
      before edge count;
      proposed after edge count;
      confidence_basis;
      explanation;
      topology_impact;
      status and validation result.

Confidence remains evidence-based, not an AI score. Exact/reversed exact with all
guards satisfied may be confidence 1.0. Guard failure is skipped, not a lower
automatic confidence.

Before opening the host operation, preflight the complete post-state in pure data:

  - validate every action and handle;
  - construct the replacement survivor DerivedEntityRecord(s);
  - replacement survivor keeps the same derived_id, kind, geometry summary,
    parent_derived_id and host_assigned_ids;
  - replacement survivor source_occurrence_ids becomes the sorted unique union;
  - construct the complete non-overlapping post-inventory;
  - compute/validate the expected derived fingerprint shape.

Then:

  1. begin one operation;
  2. dispose only non-survivor derived handles;
  3. on any dispose failure, abort the operation and return a :failed workspace
     preserving the PRE-BATCH inventory/handle registry and source fingerprint;
  4. on success, commit once;
  5. publish the already-precomputed post-workspace inventory;
  6. transition all successful actions to :applied.

Do not mutate the survivor host geometry. Only its pure-data provenance record is
replaced after the host removal batch succeeds.

Repeated apply must be a no-op. Rebuild from the same source/config must produce
the same equivalence classes, survivor IDs, provenance unions, action IDs, counts,
and derived fingerprint.

Commit/abort errors must remain visible and recoverable. Never report READY after
an uncertain host transaction.
