LOCKED V1.2 USER BEHAVIOR:
1. Add one new top-level details section named `Issues by Layer`.
2. Place it after the existing issue-type groups and before the existing `Layers` section.
3. Keep the new top-level section CLOSED by default.
4. Populate its summary before opening, using:
   `Issues by Layer — N layers (M issues)`
   where N is the number of non-empty layer buckets and M is the total number of issues in those buckets.
5. Inside it, render one bucket per layer that has at least one issue. Do not render empty layer buckets.
6. Each bucket header must show the layer name and issue count with correct singular/plural wording.
7. Issues inside each layer bucket reuse the existing issue-row renderer and existing Locate contract:
   - locatable issue: existing click-to-locate behavior remains unchanged;
   - non-locatable issue: inert, default cursor, no toast, no Ruby error.
8. Preserve the existing `Layers` rows as non-actionable. Do not turn layer-summary rows into buttons or navigation controls.
9. Order layer buckets consistently with the existing Layers role order where practical:
   Dimension -> Annotation -> Guide -> Construction -> Unknown;
   visible before hidden within a role; then deterministic name order.
   If a fallback issue cannot be matched to an existing layer record, use the established Layer0 fallback and append it deterministically without inventing host state.
10. Use textContent only for user/model strings. No innerHTML, eval, new Function, or document.write.
11. No new role colors. Reuse neutral styling; severity colors remain exclusive to issue severity.
12. Analysis remains read-only. No entity creation/deletion, property edits, layer visibility changes, active-path changes, or automatic selection/camera changes except the already-approved explicit Locate action.
