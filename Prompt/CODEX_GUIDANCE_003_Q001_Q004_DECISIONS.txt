Q003 — TARGET SKETCHUP VERSION
============================================================

DECISION: A — SketchUp 2017+ 是硬性最低兼容基线。

不得把产品最低版本提高到 SU2018+。这已经由项目背景中的 Owner 决策 #004 锁定，不是当前 Agent 可重新选择的普通实现细节。

实施要求：

- Ruby 语法和纯 Ruby Core 以 SketchUp 2017 内置 Ruby 2.2.4 为最低基线；
- 不使用 Ruby 2.3+、2.4+、2.5+ 或 Ruby 3 才支持的语法/行为作为必需依赖；
- 新版 SketchUp API 必须经 Compatibility / Capability Adapter 隔离；
- capability detection 优先于散落的版本号判断；
- Core 中不得写 SketchUp 版本分支；
- SU2017 能力缺失时才走 fallback，并在 SourceReference 中诚实标记身份稳定性。

事实纠正：

- Sketchup::Entity#persistent_id 是 SketchUp 2017 新增 API，不是 SU2018 才新增；
- SU2017 对 Edge、Vertex、Group、ComponentInstance 等本任务关键实体已经支持 persistent_id；
- 仍应使用 respond_to?/capability detection，因为并非所有实体类型在所有版本都支持 PID，而且异常/无效实体必须安全处理。

官方依据：

- https://ruby.sketchup.com/file.ReleaseNotes.html （SketchUp 2017 M0）
- https://ruby.sketchup.com/Sketchup/Entity.html#persistent_id-instance_method

因此，CURRENT_STATE.md 中“Q003=B（SU2018+ 基线，SU2017 fallback）”必须改为：

Q003=A（SU2017+ 硬基线；Ruby 2.2.4；PID 使用 capability detection）。
