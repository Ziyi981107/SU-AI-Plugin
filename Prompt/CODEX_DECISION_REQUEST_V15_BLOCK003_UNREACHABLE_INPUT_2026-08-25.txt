THE QUESTION (in plain language)
--------------------------------
The V1.5 Phase 1 vertical slice tries to remove duplicate
edges inside a single "parent container" (for example,
inside one ComponentDefinition, or inside one
ComponentInstance of a definition). The "duplicate" means
two edges with the exact same endpoints.

The proposal assumes that real SketchUp can hold two such
edges in the same place. But SketchUp's official
documentation says the native Line tool merges coincident
edges, and the Ruby API `Entities#add_line` behaves the
same way as the native tool.

If real SU2020 merges coincident edges, then the input the
vertical slice is meant to repair CANNOT EXIST in real
models. The vertical slice becomes unreachable.

The repository has NO real-SU2020 capture that proves the
input is reachable. The Agent has not searched the
machine beyond the repository and the master plan file,
per the policy in the recovery instructions.

THE THREE OPTIONS (Product Owner chooses ONE)
---------------------------------------------

OPTION A — Change the vertical slice
    Drop the current SHOULD-REPAIR vertical slice; pick a
    different repair type that is provably reachable on
    real SU2020. New CodeX Pre-build Review required.

OPTION B — Relax the provenance contract
    Allow some cross-occurrence duplicates (for example:
    two coincident edges that live in different
    ComponentInstances of the same definition, in the
    same world position). This CONFLICTS with master plan
    §17.2, which currently forbids it. Requires a new
    CodeX Pre-build Technical Preview BEFORE any
    implementation. High source/data risk: it could
    silently destroy intentional mirrored geometry.

OPTION C — Audit-only Phase 1
    Keep the proposer / detector but do NOT auto-apply.
    Phase 1 becomes a report-only feature: the dialog
    shows "would-remove N edges inside container X". No
    mutation. Safe regardless of whether the input is
    reachable. The user value is reduced (no auto-fix)
    but the safety is total. New CodeX Pre-build Review
    required for the audit-only re-scoping.
